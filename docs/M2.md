# M2 — Bidirectional port-I/O protocol

## ABI contract used

The local Linux UAPI header and official [KVM API documentation](https://docs.kernel.org/virt/kvm/api.html) define `KVM_EXIT_IO` in `kvm_run` as direction (`IN=0`, `OUT=1`), element size in bytes, port, count, and `data_offset` relative to the beginning of the mapped `kvm_run` area. The payload occupies `size * count` packed bytes. OUT data is read from that offset; IN response bytes are written there before the next `KVM_RUN`, which completes the pending operation.

On Linux/amd64 the relevant offsets are 32, 33, 34, 36, and 40 respectively; the I/O metadata ends at byte 48. The implementation bounds-checks the full payload before slicing and only completes the matching pending IN exit.

## Scope implemented

- `internal/device/PortIO` handles console output (`0xE9`), host input (`0x5050` → `42`), guest result (`0xF4`), and explicit unsupported port/direction errors.
- `internal/guest.DemoProgram()` returns a defensive copy of the documented 18-byte raw x86 guest payload.
- `internal/kvm.VCPU.Run()` decodes KVM I/O exits and copies OUT data out of the mapped region. `CompleteIO()` writes the exact-size IN response into the checked mapped range before the next run.
- `internal/vmm.RunDemo()` dispatches I/O, resumes the guest, rejects unexpected exits, and returns the semantic transcript.
